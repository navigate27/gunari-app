# Gunari

> Every night tells a story.

Gunari is a mobile-first web app that recreates the night sky from a meaningful moment — a date, time, and location — and renders it as a downloadable, shareable artwork. It is a memory experience, not an astronomy tool.

Built as a client-side-only MVP: no database, no auth, no backend. All astronomy calculations run in the browser.

## Tech stack

- **Framework:** Next.js 15 (App Router)
- **Language:** TypeScript
- **UI:** Tailwind CSS v4, shadcn/ui, Lucide icons
- **Typography:** Cormorant Garamond (display) + Geist (UI), via `next/font`
- **Animation:** Motion
- **Astronomy:** Astronomy Engine + a filtered Hipparcos star catalog
- **Rendering:** HTML5 Canvas API (pixel-perfect PNG export at 1080×1920)
- **Location:** Photon geocoding (OpenStreetMap data, no API key)
- **Map data:** OpenStreetMap via Overpass (cached `/api/osm` route), or Protomaps vector tiles when `NEXT_PUBLIC_PMTILES_URL` is set (Map Print)
- **Hosting:** Vercel

## Getting started

```bash
npm install
npm run dev
```

App runs at http://localhost:7842.

## Environment variables

No environment variables are required in development. Location search uses Photon and Map Print uses Overpass, both public OpenStreetMap services that need no key. Photon is called from the browser; Overpass is called through the app's `/api/osm` route, which caches results (in memory, plus CDN headers) so repeat views don't hit the shared servers, and the browser falls back to Overpass directly if the route is unavailable.

Optionally set `NEXT_PUBLIC_SITE_URL` (see `.env.example`) so share links and the sitemap use your own domain.

Map data is © OpenStreetMap contributors, credited on the `/map` page.

### Map Print tiles (Protomaps)

Map Print can read pre-built vector tiles, so panning and zooming only fetch a few small tiles. With no tile source set, or when the tiles fail or come back empty, it uses the cached Overpass route above.

Set `NEXT_PUBLIC_PMTILES_URL` to one of:

- A **tile template** such as `https://api.protomaps.com/tiles/v4/{z}/{x}/{y}.mvt?key=YOUR_KEY` (the Protomaps API; get a key at <https://protomaps.com>).
- A **PMTiles archive** you host, read with range requests. Cut a region from a daily build (<https://maps.protomaps.com/builds/>) and upload it to storage that allows CORS (Cloudflare R2 is the usual choice; allow `GET` and `HEAD`, the `range` and `if-match` request headers, and expose `etag`):

```bash
pmtiles extract https://build.protomaps.com/YYYYMMDD.pmtiles region.pmtiles --bbox=MIN_LON,MIN_LAT,MAX_LON,MAX_LAT --maxzoom=15
```

Protomaps' public demo file (`demo-bucket.protomaps.com/v4.pmtiles`) is unreliable and has no CORS headers, so don't use it. The data is OpenStreetMap (ODbL), so keep the attribution on the page.

## Star catalogs

The star and Milky Way data are generated by build scripts and written to `public/`:

```bash
npm run stars       # build public/stars.json (filtered Hipparcos subset)
npm run milkyway    # build public/milkyway.json (isophote polygons)
npm run catalogs    # both
```

`public/stars.json` is gitignored (regenerable). `public/milkyway.json` is committed. Re-run `npm run catalogs` whenever the source scripts change.

```
public/             # static assets + generated JSON

tech-stack          # locked tech stack
```

## Deploy to Vercel

1. Run `npm run build` locally to confirm the build passes.
2. Push the repo to GitHub (Vercel doesn't import from Forgejo).
3. Import the project on vercel.com — Vercel auto-detects Next.js. Accept the defaults.
4. Optionally add `NEXT_PUBLIC_SITE_URL` under **Settings → Environment Variables**.
5. Make sure `public/stars.json` and `src/lib/content/pairs.ts` are available to Vercel — either commit them, or set the build command to `npm run catalogs && next build`.
6. Each push to `main` auto-deploys to production; PRs get preview deployments.

## Philosophy

Gunari is not about stars. It is about memories. The stars simply help people revisit the moments that shaped their lives.
